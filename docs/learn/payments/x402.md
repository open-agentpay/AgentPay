# HTTP 402 & The x402 Protocol

The HTTP specification has reserved status code `402 Payment Required` since its inception, anticipating a future where web resources could be purchased directly over HTTP.

## The x402 Protocol Standard

The open x402 protocol builds upon HTTP 402 to establish standardized machine-to-machine payment handshakes:
1. **Initial Probe**: The client requests a protected endpoint without payment headers; the server returns `HTTP 402` with a `PAYMENT-REQUIRED` challenge payload (pricing, payment scheme, settlement asset, expiry).
2. **Authorization Generation**: The client inspects the challenge against local budget policies, selects a payment path, and generates an authorization signature (e.g. EIP-3009/EIP-712 or an API Key authorization).
3. **Replay & Fulfillment**: The client replays the original HTTP request with a `PAYMENT-SIGNATURE` header; the server verifies the signature and fulfills the request with `200 OK`.
