# AgentPay 2026 年底研发计划

> 周期：2026-10-17 至 2026-12-31　｜　假设投入：每周 10–15 小时　｜　估时单位：小时（h）

## 1. 目标

**年底定义：把基础流程跑通。**

> 一个 Python Agent 通过 AgentPay 调用被网关保护的付费 API：正常请求自动付款成功；陷入循环乱花钱时被防火墙熔断；上游失败或网络超时后恢复，不重复扣款。

**范围决策**

| 做 | 不做（推迟到 2027 / v0.2.0） |
|---|---|
| Python 买方 SDK（策略引擎、x402 V2 拦截器、EIP-712/3009 签名） | Java Spring Boot starter |
| 三态状态机 + SQLite 持久化 + 幂等恢复 | TypeScript 客户端 / Express / Fastify |
| 最简自托管网关（Python 参考实现，语言中立 YAML 配置 Schema） | **GoLang 云原生高性能网关、审计链、结构化日志** |
| Mock Facilitator + Arbitrum Sepolia Testnet 真实链上结算 | 控制台 API、独立对账服务、PostgreSQL、KMS |
| **Gas 模式 1：卖方/Facilitator 全额代付补贴**（L2 极低 Gas，买方零 Gas） | **Gas 模式 2（动态 Gas 加价分摊）与模式 3（批量聚合/状态通道结算）** |
| LangChain 付费工具 + 失控循环 Demo | 公共发现目录、托管平台、动态定价 |

## 7. 风险

| 风险 | 应对 |
|---|---|
| x402 V2 规范与预期不同或有变动 | 第 0 周调研；协议变化只影响编解码与拦截器层 |
| Arbitrum Sepolia 测试网水龙头与网络延迟 | 提前配置好测试网代币与备用 RPC；Facilitator 保持异步结算架构，支持回退到本地 Mock 双链路模式 |
| 范围蔓延 | 新功能一律进 `v0.2` 标签，不插队 |
| 精力被其他项目分走 | 每周一个可验收产物，落空也不留半成品 |
| 安全与合规 | 明确标注实验性；仅使用测试网和测试代币；不运营公共 Facilitator |

## 8. 年底完成的定义（Definition of Done）

1. `make demo` 展示：正常付款成功、超额被拒、循环被熔断。
2. 上游 5xx 或网络超时后，故障注入测试证明不重复扣款。
3. 买方、网关、上游三段链路有端到端测试，CI 绿。
4. 陌生人按 README 15 分钟内能跑通。
5. 文档明确标注实验性与已知限制。
