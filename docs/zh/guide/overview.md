# 项目概览

::: warning 实验性项目
AgentPay 处于活跃研发阶段，尚未经过独立第三方安全审计。当前仅限在测试网与测试代币环境中使用，请勿接入生产主网资金。
:::

## 什么是 AgentPay？

**AgentPay** 是专为 AI Agent（自主智能体）设计的**金融防火墙与自主支付网关**。

随着大语言模型通过 Tool Calling / MCP（Model Context Protocol）接入外部服务，Agent 开始频繁调用需要付费的 API、数据源及算力服务。传统的 API Key 预付费或人工绑卡模式面临两大痛点：
1. **失控循环（Runaway Loop）与盗刷风险**：Prompt 注入或代码死循环可能在极短时间内耗尽账户余额或透支信用卡。
2. **私钥暴露风险**：若直接将区块链私钥或支付凭据注入 Agent 上下文，极易因 Prompt 泄露或模型幻觉导致资产被盗。

AgentPay 扮演 Agent 与付费服务之间的**受控代理屏障**，为每个 Agent 提供严格配额、细粒度策略防护以及基于 [x402 规范](/zh/specs/state-machine) 的自动化支付结算。

## 解决的核心问题

```
+------------------+         +-------------------------+         +--------------------+
|     AI Agent     |         |    AgentPay Gateway     |         |  Upstream Service  |
| (No Private Key) | ------->|   (Financial Firewall)  | ------->|   (HTTP 402/x402)  |
+------------------+         +-------------------------+         +--------------------+
                                | Policy & Budget Guard
                                | Wallet Hold & Capture
                                v
                     +---------------------+
                     | PostgreSQL / Ledger |
                     +---------------------+
```

- **私钥不落模型**：Agent 仅持有租户签发的 API Key（`apk_live_...`），签名与链上资金交互完全由网关后端 Facilitator 或内部账本托管。
- **金融防火墙策略**：基于单笔限额、24小时滚动预算、白名单收款地址、速率限制与熔断机制，杜绝 Agent 失控消费。
- **资金账本与审计跟踪**：支持精确到纳秒的不可变双录账本与状态机，保证扣费、履约与退款状态绝对一致。

## 两种支付结算模式

AgentPay 支持双轨结算模式，兼顾微支付性能与去中心化需求：

| 模式 | 适用场景 | 结算机制 | 性能与成本 |
|---|---|---|---|
| **托管预付钱包 (Wallet Path)** | 高频微支付、企业内部 Agent 共享资金池 | 网关内部原子冻结（Hold）与结算（Capture），PostgreSQL 行级锁记账 | 毫秒级延迟，零链上 Gas |
| **链上结算 (On-chain Path)** | 跨组织调用、去中心化服务协议 | 支持 Arbitrum Sepolia 等 L2 网络的智能合约，异步监听交易确认 | 链上确权，不可篡改 |

## 当前状态与路线图

- **当前实现（v0.1.x）**：
  - **核心网关**：Go 高性能反向代理网关（`gateway-go`），内嵌策略引擎与钱包服务。
  - **客户端 SDK**：Python 异步 SDK（支持 MCP 工具集成与自动化 402 协议握手）。
  - **存储底座**：PostgreSQL 16 + 多租户隔离数据模型（行级安全隔离）。
  - **测试网络**：Arbitrum Sepolia（`eip155:421614`）。
- **后续规划**：
  - 多语言客户端 SDK（TypeScript / Node.js、Go、Rust）。
  - 分布式多节点网关集群与企业级管理控制台。
